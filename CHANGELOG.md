# Changelog

Public-facing changelog. Internal incident/audit detail is kept in `docs/private/CHANGELOG.full.md` (gitignored).

## [Unreleased]

### Security
- **LAN TLS now fails closed** — LAN remote control no longer falls back to plaintext on `0.0.0.0` when certificate or fingerprint setup fails.
- **Bounded WebSocket delivery** — each remote stream now has a fixed 1,024-event queue with observable overflow handling instead of an unbounded memory sink.
- **VS Code Webview hardening** — sidebar and log panels use nonce-based CSP, safe script-value serialization, DOM event listeners, and `textContent` instead of dynamic `innerHTML`/inline handlers.
- **Transactional token rotation** — a new remote token becomes live only after its runtime snapshot is durable; a failed write preserves the old token, server handle, and existing authenticated streams, while a successful rotation swaps credentials and closes every old stream as one transition.
- **Native LAN certificate pinning** — Capacitor iOS direct-LAN REST and WebSocket traffic uses the native transport to verify the exact SHA-256 fingerprint of the paired self-signed leaf certificate. Missing or mismatched pins fail closed with no Web transport fallback, and a replaced certificate requires explicit re-pairing.
- **Browser PWA LAN boundary** — direct LAN endpoints are disabled in the browser PWA, which now requires a publicly trusted HTTPS Cloudflare Tunnel. In LAN mode the server also rejects browser-marked or unmarked protected requests and serves an iOS app/Tunnel explanation instead of the PWA. The self-signed certificate's missing dynamic LAN-IP SAN is handled only inside the native iOS pin-verification path.

### Changed
- **CI and release gates** — CI now covers Rust formatting/all targets, desktop/mobile production builds, Swift pinned-transport tests, an unsigned iOS simulator app build, the landing site, and the VS Code extension. Distribution releases fail before upload when versions, tags, credentials, Developer ID identity, or updater artifacts are missing or inconsistent.
- **Version ownership** — desktop release surfaces are synchronized and checked from one canonical version; iOS, VS Code extension, and private build-package versions are explicitly independent. Living documentation no longer hard-codes volatile test counts.
- **Rust toolchain baseline** — the repository, Cargo MSRV, CI, release workflow, and development docs now use Rust 1.88, the actual minimum required by the locked Tauri dependency graph. Policy tests reject future drift between those pins.
- **Clippy policy** — every Clippy warning is fatal on the pinned Rust toolchain with no exemptions: the pre-existing positional-format style migration (228 call sites) was completed mechanically via `clippy --fix` and the temporary `uninlined_format_args` allowance removed.
- **Build-cache hygiene** — `pnpm tauri dev`/`build` (and the install/release scripts) now run `scripts/sweep-target.sh` first, pruning Rust artifacts in `app/src-tauri/target/` older than `SWEEP_DAYS` days (default 7, via `cargo-sweep`) plus any from uninstalled toolchains, so the Tauri debug target no longer balloons into tens of GB. `SWEEP_DAYS=0` disables it; no-op when `cargo-sweep` isn't installed.

### Fixed
- **Release documentation** — the README and landing site now point to the published v0.3.0 DMG, roadmap status reflects the completed release, and repository-root test commands resolve correctly.
- **Mobile alert overlap** — an in-flight declared-port conflict poll now blocks overlapping interval ticks, preventing stale state replacement and duplicate notifications while still resuming on the next interval.
- **VS Code keyboard actions** — pressing Enter on a start/stop/restart button no longer bubbles into the parent row and opens the log panel as a second action.
- **WebSocket termination** — peer EOF/errors and closed producer channels now end the forwarding task instead of leaving an idle upgraded connection waiting indefinitely.

### Testing
- **Remote boundary integration** — real Axum router and TCP WebSocket tests cover bearer/subprotocol auth, fail-closed empty tokens, failed-auth bans, request limits, protocol token non-reflection, event delivery, rotation shutdown, stale reconnect rejection, transactional persistence failure, LAN pre-bind TLS failures, and the production queue boundary.
- **Client and repository gates** — mobile pairing/reconnect/notification tests, executable jsdom VS Code Webview security/action tests, Astro diagnostics, and isolated positive/negative release-document policy tests now run in CI and the release quality gate.
- **Native pinning gates** — Swift tests exercise fingerprint normalization, exact SecTrust leaf match/mismatch, challenge-host binding, and redirect restrictions; a localhost self-signed TLS check confirms a correct pin succeeds and a wrong pin is rejected. The iOS app target also builds unsigned for a generic simulator with the native plugin linked.

## [0.3.0] - 2026-07-09

Durable inputs live in `.design-sync/` (config, 12 authored previews, conventions header, `rebuild-css.sh`); build artifacts are gitignored and re-sync is one driver command.

Backed by a behavior-preserving decomposition of `ProcessGrid` into a reusable `ScriptRow` + `useScriptActions`/`useTunnelLauncher` hooks.
- **Multi-project log tracking** — the log drawer now keeps a global tab pool (cap 8) so logs aren't lost when you switch projects or work from the global view.
- **iOS App Store prep** — `PrivacyInfo.xcprivacy` privacy manifest, `NSLocalNetworkUsageDescription` + `ITSAppUsesNonExemptEncryption=false` + `UIRequiresFullScreen=false` in Info.plist, "How it works" explainer card on the pair screen so reviewers understand the companion-app model. Submission checklist and review notes in `docs/private/` (gitignored).
- **Auto-updater** — Tauri updater plugin wired to GitHub Releases. Check & install from Settings.
- **Release automation** — `scripts/release.sh` and `.github/workflows/release.yml` build, codesign (Developer ID), and notarize DMGs. Tag push (`v*.*.*`) triggers a draft Release.
- **Docker Compose integration** — register `docker-compose.yml` stacks, one-click up/down/ps from the dashboard.
- **Persistent logs (sqlite FTS5)** — each process line is appended to `logs.db` with full-text index. Log viewer gains a search input that queries history beyond the 5 000-line memory buffer.
- **Onboarding** — first-run 3-step overlay: select folder → scan scripts → start the first one.
- **Settings dialog** — log buffer size slider, launch-at-login toggle, LAN remote opt-in, port alias editor.
- **Auto-restart policy** — per-script structured policy (`enabled / max_retries / backoff_ms / jitter_ms`). Legacy `auto_restart: true` still works.
- **Graceful shutdown order** — stopping a script first stops any scripts that declare it in `depends_on`.
- **Crash log** — panic hook writes to `~/Library/Application Support/procman/crash.log` with stderr mirror, 1 MB rotation.
- **Audit log rotation** — remote API audit log rotates at 5 MB × 3 keep.
- **Start-at-login** — LaunchAgent plist generated on demand.
- **VSCode extension** — sidebar for process control (read-only scan of `launch.json` / `tasks.json`).
- **Runtime snapshot IPC/events** — desktop frontend can bootstrap process + port ownership state from one backend command, then consume lightweight `runtime://delta` metrics and ports updates instead of stitching together separate process, port, and descendant PID calls.
- **Visibility-aware frontend polling** — dashboard, remote status, tunnel status, and declared-port probes pause while the document is hidden.
- **Multi-window logs + terminal** — process logs can be torn off into dedicated Tauri windows, and scripts can run in an interactive xterm.js PTY shell with stdin/resize support.
- **Scheduled execution** — scripts can repeat on five-field local-time cron expressions.
- **Mobile notifications** — the mobile companion can alert on script crashes, declared-port conflicts, and sustained procman unreachable states.

### Fixed
- **Updater manifest** — `latest.json` no longer advertises a `darwin-x86_64` platform pointing at the Apple-Silicon build (procman ships an `aarch64` DMG only); Intel entries were a false promise that would hand an arm64 binary to an Intel Mac.
- **Crash log preservation** — a crashed (or auto-restart-exhausted) process is now retained in a `Crashed` state instead of being immediately removed, so its in-memory log buffer survives for post-mortem (`log_tail` / `log_search` keep returning the final output). A new `dismiss_process` command clears a stopped/crashed card; restarting also clears it. `wait_for_dependencies` and the metrics/port-ownership paths treat only `Running` entries as live, so a crashed dependency never satisfies a dependent and a reused dead PID is never sampled or swept.
- **Clean-install mobile embed** — `scripts/install.sh` did not build `mobile/dist` before `pnpm tauri build`, so `rust-embed` shipped an empty SPA and LAN/mobile/QR pairing failed with a silent 404 on the README's primary install path. Mobile build is now a shared prerequisite (`scripts/lib-build.sh`) used by `install.sh` and `release.sh`.
- **vscode-extension live WebSocket** — the sidebar and log-panel sockets authenticated with a legacy `?token=` query string the server ignores, so live status/logs sat in a permanent 401 / 3-second reconnect loop. Both now send the token via the `procman-token.<token>` `Sec-WebSocket-Protocol` subprotocol the server expects.
- **v0.3 review hardening** — an adversarial code review of the refactor surfaced and fixed:
  - *Quit safety (HIGH)* — the app-exit `killpg`/descendant sweep and the confirm-quit count now filter `pm.list()` to `Running`, so a retained `Crashed` entry's dead (possibly OS-reused) PID can no longer be SIGKILL'd on quit nor inflate the "N running?" prompt.
  - *Token revocation (HIGH)* — rotating (or stopping) the pairing token now force-closes every open WebSocket via a per-server broadcast the socket loop selects on; an upgraded socket detaches from axum's graceful shutdown, so a rotated/leaked token would otherwise keep streaming.
  - *Group launch (MED)* — a crashed in-group dependency now fails the readiness gate immediately instead of blocking the sequential launch for the full 30 s (which cascaded onto every later member).
  - *Rate limiter (MED)* — authenticated requests are no longer double-counted (a budget-free ban check), restoring the full 60 req/min per IP.
  - *Lower-severity* — PTY exit sets the `exited` flag synchronously to close a reaped/reused-PID `killpg` window; audit-log disk writes move off the async worker (`spawn_blocking`); the v3→v4 migration rescues quoted-string / float `expected_port` values (warns instead of silently dropping unusable ones); the WS handshake never echoes the token subprotocol in its response; a failed port-status poll preserves the panel instead of blanking it; mobile port ownership is PID-verified against the backend (not declared-number match); and the 5 s metrics tick no longer resurrects a stale interactive `kind` for a crashed row.
- **Stabilization pass** — runtime, restore, and resource hardening (verified race-safe core kept additive):
  - *Auto-restart* — `max_retries` now bounds **flapping** (consecutive rapid crashes) rather than lifetime restarts: a service that stays up ≥ 60 s before crashing resets its retry budget, so a long-stable service that crashes once is never permanently abandoned. The computed backoff is floored to 250 ms, so a `backoff_ms: 0` config can't produce a zero-delay crash→respawn storm.
  - *Concurrent start* — `spawn_inner` claims a per-id in-flight slot, so two concurrent starts of the same script (desktop + remote + scheduler) can't both spawn a child and orphan the first (a port-binding process `kill()` could never reach); the loser gets `start already in progress`.
  - *Scheduler* — a scheduled script's (up to 30 s) dependency wait + conflict check + spawn runs in its own task, so one unready dependency no longer stalls sibling scheduled scripts or delays the next tick.
  - *Restore durability* — runtime state is flushed synchronously on a graceful quit (a script started/stopped in the last 500 ms debounce window is no longer lost from the next-launch restore set), and the atomic config/runtime writes now `fsync` the parent directory so the rename survives power loss.
  - *Corruption recovery* — a corrupt `config.yaml` no longer bricks startup; it (and a corrupt `runtime.json`) is quarantined to a `.corrupt-<ts>` sibling and the app starts from defaults with a logged warning, instead of panicking (config) or silently resetting the restore set + remote token (runtime).
  - *Tunnel stop* — `stop_tunnel` verifies the pid is still a `cloudflared` process (`ps`-identity check) before SIGTERM/SIGKILL, so a recovered tunnel's stale/reused pid can't get an unrelated process killed.

### Changed
- **Remote API hardening** — LAN mode is opt-in (off by default) and can be bound to TLS via a self-signed certificate when enabled. Rate-limiting on authenticated routes. CORS tightened. WebSocket bearer token moved from query string to `Sec-WebSocket-Protocol`.
- **Remote audit persistence** — the remote control-plane audit log now persists to disk (`~/Library/Application Support/procman/audit.log`, 5 MB × 3 rotation) instead of an in-memory ring that was lost on restart; the disk-backed `with_file` path was previously dead code. Rotating the pairing token now restarts the server on the same port so existing WebSockets are dropped and forced to re-handshake.
- **Build/CI pipeline** — `build-dmg.sh` removed (folded into `release.sh`); CI now runs `vitest` and `eslint` as gates, builds `mobile/dist` before the Rust job so `cargo test` exercises the real embed, and pins Node to `.tool-versions` (24).
- **Sidebar version footer** — now reads the real app version via `getVersion()` instead of a hard-coded `v0.1.0`; `ProcessGrid` debug logs are gated behind `import.meta.env.DEV`.
- **Port-status polling (perf)** — port-ownership resolution (`ps` + per-listener `lsof`) is now cached for 500 ms on read paths and exposed through a single `port_status_all` command / `POST /api/ports/status` route, so polling N scripts costs one ownership snapshot per cycle instead of N (`ps`×N + `lsof`×2N). Desktop, mobile, and REST were migrated together. Pre-spawn conflict checks deliberately bypass the cache and stay fresh.
- **`stop` descendant sweep** — `kill()` snapshots port-holding descendants before SIGTERM (to SIGKILL detached daemons — the Gradle/launchd JVM, etc. — that escape `killpg`) for every *live* script, gated on liveness only. (An interim pass gated this on declared ports for speed, but a port-free script can still spawn a port-binding daemon, which then leaked across stop/restart; correctness wins over the saved `lsof` on the user-initiated stop path.)
- **Backend-owned running state** — the session-restore set (`last_running`) is now owned by the backend `ProcessManager` (marked on every spawn path: start / group / remote / auto-restart) instead of the frontend reacting to status events, so it stays correct when the window closes or a process is started remotely. User-explicit stop / dismiss / delete and clean self-exit clear it; restart and app-shutdown kills deliberately do not, so the restore set survives those transitions (a generation guard prevents a stale clean-exit from clobbering a coincident restart). Startup orphan-port cleanup no longer races the restore prompt by clearing the set.
- **Single process runtime** — the interactive PTY shell is no longer a parallel runtime. `ProcessManager` now owns the lifecycle of every running script (piped *and* PTY) via `register_pty` / `notify_pty_exit`, so PTY-backed runs get the same race-safe group kill (`killpg` → grace → `SIGKILL` → orphan sweep), crash classification + log retention, CPU/RSS metrics, and session-restore marking as piped runs. `PtyManager` is demoted to a PTY-I/O front-end (write / resize / scrollback). A script can no longer run as both a piped process and a PTY at once (the `register_pty` `is_live` guard turns a second start into a uniform kill-and-restart), and `ProcessSnapshot` carries a `kind` (`piped` / `pty`) so the UI badges interactive runs. The verified piped race-safety core is unchanged (PTY support is purely additive).
- **Single launch-ordering engine** — `depends_on` topological sort (`resolve_dep_order`) was promoted from test-only code to the production primitive behind group launches and session restore; `run_group` starts members in dependency order (stable tie-break on the user's arrangement) and readiness-gates each on its in-group dependencies instead of a blind 400 ms stagger. Session restore (`last_running_ordered` + `RestorePrompt`) fires in dependency order via `Promise.allSettled`, removing a possible 30 s serial readiness stall.
- **Crash dismiss** — crashed processes (project view and global view) now expose a "Dismiss" action that clears the retained entry + log buffer (`dismiss_process`).
- **Unified in-app feedback** — every OS `alert()` / `window.confirm()` on the desktop is replaced with the in-app glass toast / `ConfirmDialog`; start / restart / group / port-kill / tunnel failures now surface as a toast with a one-tap **Retry** action, and the global "All running" Start uses the same Kill-&-start / Start-anyway port-conflict dialog as the project view. The **mobile companion** now matches: a glass toast + confirm sheet (`mobile/src/feedback.tsx`, mirroring the desktop `useToast`/`useConfirm` API) replaces its remaining native `alert`/`window.confirm` across run-group, port-stop, action errors, and disconnect.
- **Single port model** — the legacy `Script.expected_port` scalar (long marked for removal) is gone; `ports[]` is now the only port model. A config **v3 → v4** migration promotes any legacy `expected_port` into `ports[0]` at the raw-YAML level (so hand-edited configs keep working and conflict detection is preserved), the per-save `expected_port` copy loop is removed, and the always-`Tcp` `PortSpec.proto` dead abstraction + scan-time dead code are dropped.
- **ScriptEditor progressive disclosure** — the script form now shows name / command / ports up front and tucks env-file, `depends_on`, auto-restart policy, and schedule behind an Advanced section.
- **Mobile parity** — the companion app gains one-tap group run (new `POST /api/groups/:id/run` route reusing the desktop's ordered + readiness-gated `run_group`), a Stop action on ports (stops the owning registered script — no arbitrary port kill, audited), and ANSI-colour log rendering; dead API surface trimmed.
- **Config migration v2 → v3** — schema carries `auto_restart_policy`, `lan_mode_opt_in`, `start_at_login`, `onboarded`. Safe downgrade-compatible via serde defaults. (Prior migration step; the **Single port model** entry above carries the schema to **v4** — both run in sequence on load.)
- **Process status** — backend broadcasts CPU/RSS metrics as `runtime://delta` updates, with the legacy `process://metrics` event kept for compatibility, replacing per-client polling.
- **Port scanning** — 500 ms cache on `lsof` listings and a batched runtime ownership cache avoid N× calls per polling interval.
- **CPU footprint** — metrics broadcaster interval 2s → 5s and pauses while the window is hidden / unfocused. New user config default `port_poll_interval_ms` is 5s. Background CPU drops from ~45% to single digits.
- **Memory / footprint** — log ring buffers no longer pre-allocate the full 5 000-line capacity on spawn (cold reservation ~10 KB vs ~195 KB; a noisy process still tops out at the cap), and a retained `Crashed` buffer `shrink_to_fit`s once it stops receiving output. `logs.db` opportunistically reclaims after a retention trim — bounded WAL-truncate checkpoint + bounded FTS5 merge (amortized to every Nth trim), no exclusive-lock VACUUM stall. The mobile bundle code-splits `html5-qrcode` (one-time pairing only) behind a lazy boundary, cutting the initial JS from ~690 KB to ~319 KB (gzip ~205 KB → ~104 KB).
- **Remote access UX** — LAN server status now reports whether TLS is active, QR/URL display switches to `https://` for TLS sessions, and backend LAN start is gated by the user opt-in setting.
- **Docs** — planning artefacts moved to `docs/archive/`. Active design docs live directly under `docs/`.
